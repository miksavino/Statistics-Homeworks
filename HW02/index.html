Encryption and Decryption Procedure

  1. Key Generation (Recipient)
    The recipient chooses a scalar private key k from the cyclic subgroup order, and computes the public key Q = k · G using elliptic curve scalar multiplication.
    The private key acts as a mathematical trapdoor hold exclusively by the recipient. It is required during decryption to remove the blinding mask.
    The public key is used by any sender to encrypt a message without knowing the recipient's private key.
  2. Plaintext Embedding (Sender)
    The numeric plaintext message m is encoded by scalar multiplication with the base generator G: P_m = m · G
  3. Encryption (Sender)
    The sender draws a random scalar nonce r (called ephemeral key) to ensure randomized encryption, and computes:
    • the public ephemeral hint C₁ = r · G
    • the shared blinding mask S = r · Q = r · (k · G)
    • the masked ciphertext point C₂ = P_m + S = m · G + r · Q
    The transmitted ciphertext is the point pair (C₁, C₂).
  4. Decryption (Recipient)
    Using its private key k, the recipient recovers the exact shared mask from C₁: S' = k · C₁ = k · (r · G) = r · (k · G) = S
    Subtracting S' from Subtracting S' from C₂, the recipient is able to remove the mask and isolate the message point: P_m = C₂ - S' = (P_m + S) - S.
    Since P_m = m · G, the recipient solves the discrete logarithm to recover the original integer scalar m.

Toy ECC vs. Caesar Cipher

  1. Encryption and Decryption Procedures
    • Caesar Cipher: A symmetric cipher based on direct modular arithmetic over a 26-character alphabet (c_i = m_i + k (mod 26)). Encryption and decryption perform inverse shifts using the exact same secret integer k. It is completely deterministic since the same character always maps to the same ciphertext letter using the same k.
    • Toy ECC: An asymmetric scheme built on geometric point addition over a finite field. Encryption uses the recipient's public key Q and a random ephemeral nonce r, yielding a point pair (C₁, C₂). Only the owner of the private key k can unmask the message point to recover the original plaintext. It is probabilistic, meaning that the same plaintext yields different ciphertexts on each run, depending on the nonce value.
  2. Key Space
    • Caesar Cipher: Has a trivial key space of 26 (k ∈ [0, 25]). Hence, an adversary can test every possible key (brute-force attack) in a fraction of millisecond.
    • Toy ECC: In this toy configuration, the private key k is constrained to the base generator G's cyclic subgroup order (for example, k ∈ [1, 8] for G = (1, 5)). In real world, the full secp256k1 has a private key space of ≈ 2256, making brute-force attacks physically impossible.
  3. Statistical Properties
    • Caesar Cipher: Provides zero diffusion or confusion. It just rotates the plaintext frequency histogram by k positions without altering the relative distribution. High-frequency letters remain identifiable as peaks in the ciphertext, making it trivial to break via frequency analysis.
    • Toy ECC: Point masking destroys linear character-to-character correlations across repeated ciphertexts. However, raw coordinate points remain algebraically constrained by the curve equation.

Effectiveness and Comparison of Attack Strategies

Since the Caesar Cipher key space is limited to 26, different cryptanalytic techniques can be evaluated:

  • Key Search (Brute-force)
    Iterates through all 26 possible shifts. It requires no statistical assumptions about language, relying instead on human inspection or a dictionary lookup to spot intelligible words.
    Brute-force is ideal when the ciphertext is short (length < 50) or when the ciphertext might use a non-English language, making frequency-based methods less reliable.
    However, brute-force requires human judgment to identify the correct plaintext: when working with very short ciphertexts, multiple shifts might produce plausible-looking results.
  • Letter-Frequency Analysis
    Compares observed character counts with the expected probability distribution of English letters (e.g., 'E' ~12.7%, 'T' ~9.1%). The best candidate minimizes the Pearson χ² metric: χ²(k) = Σ [ (Observed_i - Expected_i)² / Expected_i ].
    Highly effective for texts with length > 50, but vulnerable to statistical noise in short phrases (lentgh < 20) lacking common letters.
    Chi-squared test considers all 26 letters simultaneously rather than relying on a single most-frequent letter (simple frequency analysis), making it more reliable with short ciphertexts.
    However, the adversary needs to know or guess what language the plaintext is in.
  • N-Gram Scoring
    Evaluates the likelihood of consecutive letter transitions (e.g., 'TH', 'HE', 'IN', 'ER') using log-likelihood summation. Because adjacent letters preserve contextual morphology, n-gram scoring reliably identifies the correct key even on very short sentences.

Cryptanalytic Comparison and Security Evaluation

  • Differences from the Caesar Statistical Attack
    The Caesar attack is purely ciphertext-only and linguistic: it does not solve an underlying algebraic trapdoor but rather measures empirical deviation against English letter distributions. In contrast, this ECC attack is algebraic and deterministic: it computes points directly on the group using public generator G until matching public key Q = k · G. It requires no dictionarY or language assumptions to succed.
  • Infeasibility against Standard secp256k1
    In the toy demonstration over, the subgroup order is negligible (n ≤ 17), allowing brute-force attacks in microseconds. In standard secp256k1, the group order is a 256-bit prime: n ≈ 2²⁵⁶.
    Solving ECDLP by brute-force requires O(n) steps. Even optimal general-purpose algorithms like Pollard's rho require O(√n) ≈ 2128 point operations, exceeding the computational energy capacity of modern distributed infrastructures.
  • Weaknesses Arising from Design vs. Restricted Key Space:
    • Restricted Key Space: The vulnerability exposed in this simulation comes from parameter reduction (k ∈ [1, n-1] with small n). An adversary trivially precomputes a lookup table of multiples i · G.
    • Design Weaknesses in Toy Schemes: Basic additive ElGamal over points (C₂ = P_m + rQ) is malleable and lacks ciphertext integrity checks. In real world, protocols use hybrid standards like ECIES (combining ECDH key derivation with AES-GCM or HMAC authenticated encryption) to prevent chosen-ciphertext attacks (CCA).
