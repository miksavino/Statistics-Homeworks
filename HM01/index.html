1. Introduction: Asymmetric Cryptography & One-Way Trapdoors

In Ethereum and modern public-key cryptography, a private key is fundamentally an integer scalar k chosen uniformly at random. From this secret scalar, the associated public key Q is computed via elliptic-curve scalar point multiplication:

Q = k * G = G + G + ... + G (k times)

, where G is a generator point on the curve.

To explore these group operations, this homework models the relationship using the toy curve y² ≡ x³ + 7 (mod 17).

In an ideal cryptographic setting, each bit should have an independent 50% probability of being 1. The data shows clear deviations from this behavior: the lower bits (b0 to b3) fluctuate between 38.8% and 49.7%, while the most significant bit (b4) drops to 0.0% for x and 7.3% for y. This drop occurs because coordinates are bounded by the prime modulus 17, and no valid point on this curve has an x-coordinate of 16. These results show that the bits are correlated by the underlying curve equation rather than being uniformly distributed, which explains why raw curve coordinates must be processed by a hash function before being used as addresses.

Apparent Uniformity and Correlation between Input and Output

As k increases by 1, consecutive coordinate pairs do not follow a continuous or monotonic path. The points seem to jump unpredictably across the modular grid, giving a superficial impression of uniform dispersion. However, this sequence is strictly constrained: the generated points can never take arbitrary positions in the field, as they must satisfy the curve equation y² ≡ x³ + 7 (mod 17) and belong to the cyclic group generated by G.

In addition, while there is no obvious linear correlation between the scalar k and the resulting point Q, they remain linked by a deterministic algebraic rule: knowing Q = kG directly allows computing (k + 1)G = Q + G. This proves that point multiplication preserves the group law and geometric constraints, rather than producing statistically independent outputs.

Avalanche-like Behaviour

Because scalar multiplication preserves the group addition law, it does not provide a true cryptographic avalanche effect. Changing a single bit in the private key k can occasionally flip more than 50% of the bits in the resulting coordinates, mimicking avalanche-like behavior. However, this is only a visual artifact of the modular arithmetic: unlike a hash function, the operation never destroys the underlying algebraic relation (k + 1)G = kG + G, leaving the system fully predictable from a group-theory perspective.

Cryptographic implications

Meaningful for a OWF

Scalar multiplication acts as an asymmetric cryptographic one-way function (OWF):

  • Forward direction (computationally efficient): Computing Q = kG is straightforward and runs in polynomial time.
  • Reverse direction (computationally infeasible): Finding the private key k from the public point Q and base point G requires solving the Elliptic Curve Discrete Logarithm Problem (ECDLP). For properly chosen cryptographic curves, no classical polynomial-time algorithm exists to compute this inverse.

Meaningful for a hash function

Even though multiplying a point does not show an obvious linear pattern and can look random at first glance, it lacks the main properties of a cryptographic hash function:

  • It keeps mathematical relationships: Elliptic curve math follows clear addition rules, such as (k + 1)G = kG + G. A true hash function must destroy all algebraic patterns so that outputs cannot be linked or combined mathematically.
  • It is not statistically uniform: The data clearly shows that coordinates and individual bits have visible biases, rather than behaving like balanced random noise where every bit has an even 50% chance.

In summary, scalar multiplication works great as a one-way function to generate a public key from a private key. However, because its output keeps this geometric structure, Ethereum cannot use the raw point as an address: it must first pass the public key through Keccak-256 to scramble the bits completely and create a uniform 20-byte address.
